## 2. 为什么改为「网页端优先」

### 2.1 小程序路径的成本（已规避）

| 事项 | 小程序路径 | 网页端路径 | 节省 |
|---|---|---|---|
| 域名 ICP 备案 | 7–20 工作日 | ❌ 不需要 | ✅ |
| 小程序备案 | 1–20 工作日 | ❌ 不需要 | ✅ |
| 微信审核 | 1–7 天 | ❌ 不需要 | ✅ |
| 主体变更（个人→企业） | 约 1080 元 | ❌ 暂不需要 | ✅ |
| 微信支付 / VIP 订阅 | 必须企业主体 + 认证 | ❌ 暂不需要 | ✅ |
| 发版 | 每次都要审核 | 改完即生效 | ✅ |

**结论**：网页端在"功能验证期"的成本是 **0 元**，小程序路径至少 1000 元 + 一个月等待。

### 2.2 小程序端代码不废弃

现有 4122 行原生小程序代码**保留**，作为将来发布小程序的资产。本阶段不维护、不改动。

## 3. 技术方案

### 3.1 架构

```
家人手机浏览器（微信内置 / Safari / Chrome）
    ↓ HTTPS（内网穿透工具提供，自动配证书）
NAS 上的 Nginx（:443）
    ├── /            → 网页端静态资源（Vite 构建产物）
    └── /api/        → 反向代理 → FastAPI（:8000）
                          ↓
                  PostgreSQL 16（NAS Docker）
```

**关键点**：网页端与 API 同源（同一域名下的 `/api`），**彻底规避 CORS**。

### 3.2 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 前端框架 | Vue 3 + Vite | 与小程序观感一致；Vite 构建快，产物为纯静态文件 |
| UI 组件 | Vant 4（移动端） | 移动端优先，开箱即用 |
| 构建 | Vite | 产物可直接由 Nginx 托管 |
| 后端 | **保持现有 FastAPI，不改动** | 6777 行已跑通并通过安全修复 |
| 数据库 | PostgreSQL（NAS Docker） | 与生产一致；SQLAlchemy 双兼容层已就绪 |
| 容器 | Docker Compose | NAS 上最省事 |
| 入口 | Nginx | 静态托管 + 反代 + TLS 终止 |

### 3.3 与小程序端的关系

- **后端 API 契约完全复用**（63 个端点不变）
- 网页端的请求层参照 `miniprogram/utils/api.js` 实现，**保留相同的 token 注入 / 401 自动刷新 / 并发刷新锁逻辑**
- 差别仅在：存储用 `localStorage`（小程序是 `wx.setStorageSync`）、导航用 Vue Router（小程序是 `wx.navigateTo`）

## 4. 登录方案

### 4.1 现状问题

`wx.login` 在网页端不可用（6 处调用）。网页端需要独立的登录机制。

### 4.2 选定方案：家庭共享口令

新增 `POST /v1/auth/family-code`，用家庭共享口令换取 token。

| 优点 | 说明 |
|---|---|
| 免注册 | 家人输入口令直接进家庭，不需要邮箱验证 |
| 免邮件 | 不依赖 SMTP（邮件功能已降优先级） |
| 契合场景 | "家人内部使用"本就该低门槛 |
| 安全性可控 | 口令只在家庭内部传递；配合限流与失败锁定 |

### 4.3 保险箱的连带调整

保险箱 OTP 当前依赖**邮件验证码**（2026-11-10 刚修复完）。邮件降级后需要替代方案：

- **方案**：家庭口令 + 保险箱二次确认（短时 session，沿用现有 `vault_sessions` 机制）
- `vault_email_otps` 表保留不删（结构已含 `attempts` 限流字段，未来可复用）
- 若未来恢复邮件发送能力，可平滑切回

### 4.4 安全要求（公网暴露，必须做）

| 项 | 要求 |
|---|---|
| HTTPS | 穿透工具自动配置，**禁止明文 HTTP** |
| 登录限流 | `/auth/*` 全部加限流（当前仅部分接口有） |
| 管理端 | 确认 `ADMIN_USER_IDS` 默认为空；生产建议绑定 IP 白名单 |
| JWT | 现有实现，检查过期时间设置合理 |
| 依赖漏洞 | `pip-audit` 纳入 CI |

## 6. 实施路线

### 阶段 1：NAS 部署骨架 ✅ 已完成（2026-11-10）

**交付物**

| 文件 | 说明 |
|---|---|
| `Dockerfile` | 后端镜像，依赖层与源码层分离缓存；非 root 用户运行；含 healthcheck |
| `deploy/docker-compose.yml` | 4 个服务：`db` / `migrate` / `backend` / `nginx` |
| `deploy/nginx.conf` | 静态托管 + `/api` → `/v1` 反代 + SPA fallback |
| `deploy/.env.example` | 容器环境变量模板（真实 `.env` 已被 gitignore） |
| `tests/test_schema_consistency.py` | 35 个用例：迁移链 ↔ ORM 逐列比对 |

**关键设计决策**

1. **`/api/` → `/v1/` 路径映射** —— 前端只调 `/api/xxx`，Nginx 翻译成后端的 `/v1/xxx`。前端不必知道后端版本号，且同源部署天然规避 CORS。
2. **迁移作为独立一次性服务** —— `migrate` 容器跑 `alembic upgrade head`，`backend` 通过 `depends_on: service_completed_successfully` 等它完成。避免后端对着空库启动导致全站 500。
3. **固定 Docker 网段 `172.28.0.0/16`** —— 供 uvicorn 的 `--forwarded-allow-ips` 限定范围，不使用 `*`。
4. **`X-Forwarded-For` 信任改为显式配置** —— 新增 `TRUSTED_PROXY_HOPS`（默认 0 = 不信任）。原实现无条件信任该头，攻击者可伪造以绕过限流。
5. **CORS 默认关闭** —— 新增 `CORS_ORIGINS`，为空时不注册中间件。同源部署本就无需 CORS。

**过程中发现并修复的真实 bug**

| Bug | 影响 | 修复 |
|---|---|---|
| `quotas` / `vault_sessions` / `scenario_instances` 缺 `created_at` 列 | **建家庭接口 500**（新建家庭要写 quotas 表） | 新增 `0004_backfill_created_at` 迁移 |
| `vip_subscriptions` 缺 `updated_at` 列 | 将来更新 VIP 订阅会 500 | 同上 |
| `0003` 迁移不幂等 | 已跑过 0003 的库再执行会报错 | 改为先检查列是否存在 |
| `migrations/env.py` 无条件覆盖 `sqlalchemy.url` | 测试无法指定目标库 | 改为"显式传入优先，占位符视为未设置" |

> 这批 bug 之所以能潜伏至今，是因为**测试只覆盖了不需要写这些表的路径**。schema 一致性测试补上了这个缺口。

**验证结果（本机无 Docker，用等价方式验证）**


## 9. 关键事实备忘（2026-11-10 核验）

- **微信主体变更 AppID 不变** —— 官方文档明确「主体变更在同一账号内进行，appid 不变，小程序不会被注销」。个人转企业需公证（个人转企业主体变更需进行申请函公证或法定代表人扫脸验证），第三方代办报价含公证费 480 + 审核费 300
- **个人主体不能开通微信支付** —— VIP 订阅功能需企业/个体户主体
- **小程序 web-view 个人主体不支持** —— 仅非个人主体可配置业务域名
- **体验版免备案免审核** —— 体验成员上限：个人 15 人 / 企业 90 人
- **正式发布必须已备案 HTTPS 域名** —— 微信对所有请求域名做实时备案校验
- **Vercel Hobby 限非商业用途** —— 若将来做付费产品需升级 Pro
- **Resend 发国内邮箱送达率差** —— 保险箱 OTP 若恢复邮件发送，应改用腾讯云邮件推送
